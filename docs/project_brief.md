## 2. 과제 요구사항 (원문: `PBL 모듈 1.pdf`)

**시나리오**

- 지자체가 차량 카메라로 도로를 찍어 균열과 포트홀을 점검한다.
- 실제 영상은 다음 세 가지 때문에 손상 특징이 잘 드러나지 않는다.
  - 조도 불균일: 저조도나 과노출
  - 노이즈
  - 흐림: 차량 이동이나 촬영 환경
- 따라서 두 가지를 하는 프로그램을 만든다.
  - 전처리로 품질을 개선하고, 에지·블롭 검출, 임계값, 형태학적 연산, 연결 요소·윤곽선 분석으로 후보 영역을 추출한다.
  - 전처리 전·후 결과를 정량적으로 비교한다.

**해야 할 것**

1. 전처리 파이프라인: 영상 문제점 분석, 알고리즘 선정, 순서·파이프라인 설계, 전처리 전·후 영상 비교
2. 균열·포트홀 후보 추출: 추출 방법 분석·구현, 결과 시각화
3. 전처리 전·후 정량 비교: 아래 항목을 비교하고 분석·결론을 낸다.
   - 특징점 또는 에지 수
   - 후보 영역 수와 면적
   - 후보 추출 결과
   - 처리 시간

**제약 조건**

- 제공 데이터셋과 조별 직접 촬영 영상을 모두 쓴다.
- 방법 선택은 자유지만, 선택 이유와 근거를 설명한다.
- 전처리 전·후를 정량 비교하고, 제공 데이터와 직접 촬영 데이터의 결과 차이도 비교한다.
- 사용 알고리즘의 원리와 적용 방법을 설명한다.
- 장점·한계를 분석하고 개선 방향을 낸다.

**촬영 가이드**

- 교내나 주변 도로에서 스마트폰으로 다양한 조도·도로 상태를 담아 최소 10개 이상 찍는다.
- 반드시 인도에서만 찍는다. 차도 진입과 통행 방해는 금지다.
- 얼굴과 차량 번호판 같은 개인정보가 찍히지 않게 주의한다.

**최종 결과물**

- 프로그램: 전처리, 균열·포트홀 후보 추출, 결과 시각화
- 보고서: 문제 분석, 해결 방법·알고리즘 선정 이유, 구현 과정, 전처리 전·후 비교, 정량적 성능 비교, 결과 분석, 개선 방향, 결론
- 발표: 문제, 원인 분석, 해결 방법, 구현 결과·시연, 실험 결과 분석, 결론

## 3. 평가 기준

**반영 비율**

| 항목 | 비율 |
| --- | --- |
| 과제수행계획서 | 20% |
| 코드 및 결과보고서 | 40% |
| 발표 | 20% |
| 그룹평가(역할 분담·책임) | 10% |
| 개별평가(수업 참여·동료 평가) | 10% |

세부 항목 쪽에는 그룹·개별 평가가 '수업참여도 20%'로 묶여 있다.

**세부 기준**

- **계획서**: 다음 여섯 가지를 본다.
  - 문제 정의·분석
  - 해결 아이디어의 적절성
  - 학습과제의 구체성(문제 해결과의 연관성)
  - 실행 계획의 구체성(주차별 탐구 과제, 구현 단계, 실험·검증 방법)
  - 역할 분담 및 활동 기록(주차별 팀 논의·실험 진행 기록)
  - 수행 일정의 적절성
- **코드·결과보고서**: 다음 다섯 가지를 본다.
  - 알고리즘 구현 완성도: 조도 개선, 노이즈 제거, 특징점 추출 및 매칭, 후보 추출 등 전체 파이프라인이 오류 없이 동작하는가
  - 정량적 결과 분석: 전처리 전·후의 특징점 수, 후보 수·면적, 처리 시간
  - 실험 설계·타당성: 제공·직접 촬영 데이터를 쓰고, 조건에 따른 차이를 분석했는가
  - 코드 가독성·모듈화
  - AI 도구 활용 및 성찰: 활용 내역·프롬프트·디버깅 과정을 구체적으로 기록하고, 장점과 기술적 한계를 고찰했는가
- **발표**: 다음 세 가지를 본다.
  - 전달력·논리성
  - 시연 완성도: 실시간 또는 사전 제작 데모 영상에서 오류 없이 동작하는가
  - 질의응답: 원리, 적용 방법, 주요 파라미터 설정 이유, 실험 결과에 답하는가
- **수업참여도**: 교수자 그룹평가, 타 팀 상호평가, 팀 내 익명 동료평가(1~5점)

**주의**: 평가표에 '특징점 추출 및 매칭'과 '전처리 전·후의 특징점 수'가 직접 들어 있다. 그래서 특징점·매칭은 손상 검출에 쓰지 않더라도 전처리 전·후 비교 지표로 남겨야 한다.

## 8. 현재 결정 요약 (원본: `plan_2nd.md` 2·5·6장)

**문제 재정의**: 촬영 시점과 화질이 다른 도로 영상에서 노면을 자동으로 찾고, 그 안의 후보를 형태로 균열과 포트홀로 나눈다. 전처리는 이 결과를 개선하는지로 효과를 판단한다.

**개선 7항목**

1. 자동 노면 ROI: Lab 색 공간에서 아래 가운데 노면과 비슷하고 이어진 영역을 찾고, 닫힘·구멍 메우기를 한다. 띠 위쪽 경계를 올리는 E1b도 함께 비교한다.
2. 공통 후보 추출: 밝은 표시를 메운 뒤, 크기가 다른 두 범위의 중앙값 배경보다 어두운 영역을 뽑는다. 닫힘으로 잇고 작은 영역은 지운다.
3. 적응형 임계값: 부호 있는 잔차의 MAD(하한 있음)로 잡음 크기를 재고, 이중 임계값을 쓴다. 노면 안에서 재는 방법도 비교한다.
4. 형태 분류: 비원형도(P²/4πA)를 주 기준으로 하고, 두께(2A/P)·거리 변환 폭·solidity는 보조로 쓴다. 구멍 둘레를 포함하고, 개발용 분포로 기준을 정한다. 점수로 동작점을 정한다.
5. 상태 판정·전처리 보완: 재흐림 비율, 감마 상한 낮추기, 평활화를 CLAHE로 바꾸는 것 검토, 야간은 잡티를 먼저 처리한다. 효과는 검출 결과로 판단한다.
6. 평가 보완:
   - 판정: 후보 중심이 같은 종류 정답 박스 안에 들면 맞음(IoU 0.3도 기록).
   - 영상 단위: 손상 영상은 같은 종류 후보가 하나 이상 맞으면, 무손상 영상은 후보가 0개면 맞힘.
   - 지표: 민감도·특이도·정밀도·재현율·균형 정확도·영상당 오검출, 그리고 기준선·우연 대조군.
7. 데이터 분리와 보완: 위의 개발/시험 분할, 39장 정답 표시와 교차 검수, 인위 저하 실험(흐림·어두움·과노출·잡음).

**목표**

- **기본**(시험 152장, 전처리 끔·켬 모두):
  - 영상당 오검출을 8.1개에서 2개 이하로 줄인다.
  - 특이도를 7%에서 50% 이상으로 높인다.
  - 균열 재현율 4.9% 이상을 유지한다.
  - 정답률은 기준선 36.2%와 함께 보고한다.
- **도전**(39장, 개발 중 확인 영상): 영상 단위 정답률 60% 이상

## 11. 확인된 함정과 교훈

**기술**

- 잡음 σ를 max(r, 0)의 MAD로 재면 0이 된다. 부호 있는 잔차의 MAD로 재고 하한을 둔다. 입력이 uint8이라 σ는 1.48 간격 값만 나온다.
- 배경 창이 하나면, 반지름이 창의 약 0.4배를 넘는 포트홀은 가운데가 빈다. 그래서 두 창(띠 높이 0.5·1.0배)의 큰 값을 쓴다.
- 큰 그림자는 경계 조각만 남아 포트홀로 분류될 수 있다(United_States_004830). '넓이 > 띠의 15%' 그림자 규칙은 실제로 걸리지 않는다.
- 밝은 표시를 메우는 창보다 넓은 밝은 영역 옆은 '어두운 선' 후보가 된다(Japan_000107 자갈 경계).
- '균열 두께 ≤ 4px' 규칙은 넓은 균열을 버린다(Japan_010993). 그래서 비원형도를 주 기준으로 쓰고, 거북등 균열 때문에 구멍 둘레를 포함한다.
- 노면 마스크 v1의 실패 모양:
  - 그림자 진 노면이 빠지거나(US_004830) 햇빛 받은 노면이 빠진다(US_005996).
  - 차선이 노면을 가른다(China_MotorBike_002209).
  - 인도·흙 비탈·자갈·검은 차체가 노면으로 들어간다.
- 노면 안에서만 σ를 재는 효과는 마스크 품질에 따라 갈린다. US_005996은 19.3에서 11.9로 내려가지만, US_004830은 16.3에서 17.8로 오른다.
- 상태 판정의 함정:
  - 라플라시안 분산은 근접 골재 결에 좌우된다.
  - '평균 밝기 80 미만'은 원래 어두운 아스팔트도 어둡다고 판정한다.
  - 잡음 추정은 골재 결을 잡티로 본다.
- 데이터 관리:
  - `data/shot_log.csv`·`data/roi.csv`가 실제 파일과 일부 다르다. shot_log는 옛 이름(own_01_crack_normal 등)이고, roi.csv는 쌍 행이 다르며(pair01_B_blur ↔ 실제 pair01_B_dark, pair03~05 행 없음) 제공 13장의 condition 칸이 비어 있다.
  - 손상 없는 영상은 머리글만 있는 정답 CSV가 있어야 평가에 들어간다.
  - (해결) `gt/own_15_pothole_dark.csv`는 10/08까지 커밋되지 않았다가 10/10 `c-foundation`에서 커밋됐다.
