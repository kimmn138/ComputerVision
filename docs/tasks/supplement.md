5. 0-2로 다시 만들 수 없고 `results/` 밖에 기록도 없는 숫자(보고서 본문에만 남은 숫자)는 0단계 보고에서 절 번호와 함께 목록으로 정리한다. 기록이 있으면 그 위치를 함께 적는다.

### 2.4 τ를 어디에 적용하나

- **결정(사용자): `src/detect.py`(B 파일)의 `detect_cracks`·`detect_potholes` 마지막.** `USE_SCORE_TAU`가 켜져 있고 dark 방식이면 `score ≥ SCORE_TAU_<종류>`인 후보만 돌려준다.
- 이유: 함수 약속 표의 `detect_*(gray, road=None)` 형식과 '`road=None`이면 지금과 같음'이 그대로라 약속 변경 절차(CONTRIBUTING 7장)가 필요 없다. τ 거르기와 `pipeline.keep_on_road`의 노면 거르기는 후보마다 따로 판단하므로 순서가 바뀌어도 결과가 같다. Plan.md 3장 그림의 '점수 ≥ τ만 출력 (B)'과도 맞는다.
- legacy 방식은 score가 NaN이라 거르지 않는다(NaN ≥ τ는 거짓이라 그대로 두면 후보가 모두 지워진다).
- pipeline(C)에 두는 방법도 있지만 run_pipeline의 약속 문장이 바뀌어 7장 절차와 `check_contract` 수정이 따른다.

## 3. τ 곡선 산출물 형식

`tools/evaluate_train.py`(B 파일)에 `--tau-curve` 옵션을 더한다. 켜면 같은 실행 안에서 두 번 돈다.

1. config 그대로 한 번 돈다(τ 스위치가 켜져 있으면 τ 적용). 지금과 같은 `train_detail.csv`·`train_summary.csv`·`per_source.csv`를 쓴다.
2. 실행 중에만 `USE_SCORE_TAU = False`로 바꿔 모든 후보를 모은다. 후보마다 (영상, 종류, 점수, 같은 종류 정답 안 여부, 이웃 사진 정답 안 여부(우연 대조군))를 기억해 두고, τ 격자마다 지표를 메모리에서 다시 계산한다. 파이프라인은 다시 돌리지 않는다.

1번이 있어야 요약 표가 실제 최종 설정과 칸 하나까지 같다. 2번은 τ보다 낮은 후보까지 있어야 곡선 전체를 그릴 수 있어서 필요하다.

**τ 격자**: 종류마다 그 실행의 후보 점수 분위 0%, 1%, …, 100%와 '모두 지움'(+∞) 102개 → 균열 × 포트홀 102 × 102 = 10,404점. 영상마다 '맞힌 후보의 최고 점수', '모든 후보의 최고 점수'를 미리 구해 두면 τ마다 NumPy 비교 한 번으로 끝난다(픽셀 for 문 없음).

### 3.2 `tau_points.csv` (동작점만)

행마다 `preprocess`, `point`, `tau_crack`, `tau_pothole`, `note`와 3.1의 지표 열을 둔다. `point`는 다섯이다.

| point | 뽑는 법 |
|---|---|
| `none` | τ 없음(모든 후보) = 지금 방법의 동작점 |
| `fp1` | `fp_per_image ≤ 1.0`인 격자점 가운데 민감도가 가장 높은 점. 같으면 특이도 → 균형 정확도 → (q_crack + q_pothole)가 작은 쪽(후보를 덜 지움). 그런 점이 없으면 지표를 NaN으로 두고 `note`에 '오검출 1개 이하 불가' |
| `fp2` | 위와 같고 기준 2.0 |
| `rule1` | 채택 규칙 2·3을 재는 점. **10/13부터 `fp2`와 같은 방법으로 고른다**(`fp_per_image ≤ 2.0`에서 민감도 최대, 같으면 특이도 → 균형 정확도 → 분위 합이 작은 쪽, 3.4). 그런 점이 없으면 NaN과 `note`. **채택 규칙 2·3은 이 점에서 잰다(4.1)** |
| `config` | 1번 실행에 쓴 τ(스위치 끔이면 `none`과 같음). 참고용 |

"영상당 오검출 1개·2개 동작점의 민감도"는 `fp1`·`fp2` 행의 `sensitivity`다. 채택 규칙 1은 이 두 값으로, 규칙 2·3은 `rule1` 행으로 자동 판정한다(4.1).

### 3.3 `tau_curve.png`

- 왼쪽 그림: x = 영상당 오검출, y = 민감도. 파레토 경계(실선), 두 종류 같은 분위 선(q_crack = q_pothole, 점선), x = 1·2 세로선과 `fp1`·`fp2` 표시, `none`·`config` 점. 끔은 파랑, 켬은 주황.
- 오른쪽 그림: x = 1 − 특이도, y = 민감도. 같은 곡선 위에 '정답률 = 검출 없음' 직선(민감도 = 무손상 수 ÷ 손상 수 × (1 − 특이도), 개발셋 기울기 약 0.59)과 '균형 정확도 50%' 대각선을 긋는다. 곡선이 이 직선 위로 가면 Plan.md 3.5 (3)의 '기준선을 넘는가'에 답이 된다.
- 한글 글꼴은 `run_experiment`·`visualize`와 같은 config C 구역 `FONT_BY_PLATFORM`을 쓴다.

### 3.4 τ\*를 고르는 규칙

**결정(10/13, 사용자): fp2 점 — `fp_per_image ≤ 2`인 점 가운데 민감도 최대**(`tau_points.csv`의 `rule1` 행 = `fp2` 행). Plan.md 3.5 (3)의 '기준선을 넘지 못하면 오검출 2개 이하를 만족하는 τ를 고르고 그대로 보고'와 목표 '오검출 2개 이하'에 맞는다.

- 바꾼 이유: 처음 정한 ① '오검출 ≤ 2 중 균형 정확도 최대'(10/12 밤)는 S0·S1a~c에서 민감도가 0보다 큰 점 가운데 균형 정확도가 50%('검출 없음')를 넘는 점이 하나도 없어, 늘 후보를 (거의) 모두 지우는 점(민감도 0, 특이도 100%, 균형 50%)을 골랐다. 이 점은 τ 없음(31.0%)보다 균형 정확도가 높아 규칙 2를 '통과'하므로 E4가 '모두 지움'을 채택하게 된다(docs/part_C.md 1-3 절). 곡선 전체가 50% 아래면 '최댓값' 규칙은 곡선 끝점으로 미끄러진다.

- 이 규칙은 두 곳에 쓴다. (1) `supp` 단계의 모든 개발셋 실행에서 규칙 2·3을 잴 점을 고른다(4.1). (2) config의 τ를 정한다. config에는 E4에서 한 번, 6단계 ET에서 한 번만 쓴다(둘 다 fp2 점).
- **E4 예외 채택(10/13, 사용자)**: fp2 점에서 E4는 규칙 2를 넘었지만(균형 정확도 31.0 → 33.6%) 규칙 3을 못 넘었다(우연 뺀 균열 재현율 +14.8 → +12.2%p). 규칙 3은 후보를 만드는 방법을 바꿀 때 균열 맞힘을 잃지 않게 하려는 규칙인데, E4는 같은 후보에서 동작점을 고르는 일이고 Plan.md 3.5 (3)이 E4의 목적을 '오검출 2개 이하 τ'로 정했다. 손실은 보고서에 그대로 적는다(run_all `SUPP_DECISIONS`, `results/report/accept.txt`의 E4s).
